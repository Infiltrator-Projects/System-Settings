# System Settings forensic audit — 25 September 2026

## Scope and standard

Baseline: `bbd9cc747b3eb2afd5eca6180f17a6bed1f1cd89` (0.4.6).
Common remains pinned to `e985e88c2fbbedfe7239ee716908dc686444287a` (1.19.25).

The review traced first-party C source and headers, tests, build/package rules,
module metadata and owning documentation. Source review covered input validation,
ownership, failure paths, asynchronous completion, persistence publication and
consistency between comments and implementation. The Common dependency was
inspected at consumed contracts; this is not a fresh line-by-line audit of Common.
Historical changelog entries and the standard licence text are not new evidence
of runtime correctness. No academic accreditation or formal correctness proof
is claimed by “graduate-level”: the measurable standard here is explicit
contracts, reproducible regressions, justified ownership and honest limitations.

## Findings repaired

| Area | Defect | Repair / evidence |
|---|---|---|
| GTK construction | Four dropdown models were unreferenced after transfer-full construction | Preserve GTK ownership; actual shell fixture accesses model items and closes repeatedly |
| Window lifecycle | Repeated activation created windows; pending replies delayed cleanup until finalisation | Present existing window; close detaches panel, cancels requests, disconnects signals, removes sources |
| Service lifetime | Mutation completion carried a borrowed service past caller disposal | Per-call reference; private-bus test releases owner before delivering reply |
| Service availability | Construction could be labelled live with no usable properties; service loss suppressed observer updates | Require owner/Timezone/NTP; propagate unavailable state and disable native controls |
| Variant ownership | Rejected calls leaked floating argument variants | Launcher takes/relinquishes a local owned reference on every path |
| Model publication | Compatibility notifications could recursively save before publication; reload dereferenced a missing store | Reject re-entry, guard reload, test failure preserves committed policy |
| Coordinates | NaN bypassed simple comparisons | Reject non-finite model/metadata/zone-hint input, including unconfigured coordinates |
| Locality metadata | Load accepted invalid coordinates and silently truncated fields; output could contain partial data | Validate complete candidate and publish once; validate termination/UTF-8 on save |
| Manual time | Unbounded `%d` conversions on user input | Bounded ASCII field parser; malformed/oversized input leaves output unchanged |
| Manual date | Unbounded conversion and silent DST-gap normalisation | Fixed-width input and post-construction civil-time equality check |
| Instant capture | Date and clock were sampled separately around midnight | Derive timestamp from the already captured GDateTime |
| Zone tables | Short rows could index past the split-vector sentinel | Guard earlier fields; deterministic malformed-file regression |
| Zone authority | Legacy `/etc/timezone` could override active `/etc/localtime`; later aliases absent from selector | Prefer active link and append newly reported aliases |
| CLI transaction | Earlier options persisted before later invalid arguments failed | Stage all options, then perform one final write; fixture verifies unchanged file on failure |
| Windows parsing | Embedded NUL accepted a valid policy prefix while ignoring trailing bytes | Reject whole malformed document; Windows regression fixture |
| Windows publication | All writers reused one `.tmp` file between close and rename | Exclusive per-process/call sibling creation; clean up only owned files |
| Optional controls | Missing Cinnamon controls appeared writable | Disable absent controls; setters check value types |
| Startup | Legacy-default conversion could publish policy merely by opening the panel | Resolve absent policy in memory; persist migration only for existing documents |
| Runtime lifetime | Static GType callbacks can outlive a dynamically unloaded Calendar library | Keep accepted Linux runtime resident; fixture finalizes a registered type after provider release |
| Build/CI | MSVC warning policy absent; geocode check accepted unsupported 1.0; offline runner labels could queue indefinitely | Explicit MSVC warnings; exact 2.0 check; hosted jobs and integration dependencies |
| Documentation | README overstated Windows GUI/framework completion; preview owner and discovery comments drifted | Mark planned features; correct Common/Calendar roles, lifecycle, transaction and build contracts |

## Audit closure

The forensic pass is complete against the scope stated above: first-party
functionality, documentation and source comments were reviewed together,
identified defects were repaired, hosted CI passed on Linux and Windows,
sanitizers passed, and the resulting implementation was released. The boundaries
below are live-environment validation limits or roadmap work; they are not
uncommitted audit fixes.

## Post-audit forensic follow-up — 0.4.9

The independent review of the audit implementation added permanent coverage for
the two evidence gaps identified after 0.4.7: the private timedated fixture now
proves service-owner loss and reacquisition, and the Windows persistence fixture
runs competing child processes against one policy path to prove whole-document
publication and temporary-file cleanup. Linux locality persistence now repairs
an already-existing leaf directory to mode 0700, matching its documented privacy
contract. Normal Linux and Windows CI builds now use total logical processors
minus one, matching sanitizer and release builds.

## Remaining boundaries

This audit does not implement the planned Windows GUI, dynamic module ABI,
manifest loader, global search, navigation history or additional settings domains.
The release line includes a native `.run` source installer and bundled source
ZIP beside the Debian package. Earlier published assets remain immutable.

Real Mint validation remains necessary for polkit denial/cancellation, live
geocoding, desktop integration, manual edits across external changes, accessibility
and service restart. A successful timedated reply is reconciled with its cache
and property notifications; it is not an independent hardware-clock readback.
Ambiguous DST folds retain GLib's standard-time choice; there is no fold selector.
Locality-to-zone selection remains a representative-point heuristic, not boundary
geography. Policy and locality metadata are separate transactions; native
compatibility mirroring is best-effort. Whole-file concurrent saves are last
publication wins, not field-wise merges. The panel does not yet watch CLI policy
file changes or reload the theme when the desktop theme changes while open.
